# 토익 RC 트레이너 (TOEIC Part 5·6·7 고득점 훈련 PWA)

> 이 저장소 루트의 `index.html`은 기존 OPIc 시뮬레이터입니다. 토익 앱은 **`toeic/` 폴더**에 따로 있습니다.

TOEIC 리딩(Part 5·6·7) 전용 휴대폰 학습 앱입니다. 진단 → 약점 분석 → 맞춤 추천 → 즉시 해설·오답 원인 → 단계별 복습 → 속도 훈련 → 실전 모의고사 순서로 공부합니다. 서버·계정·유료 API 없이 정적 파일만으로 동작하고, 기록은 기기 브라우저(IndexedDB)에 저장됩니다.

LC(Part 1~4)는 기기 음성과 그림으로는 실제 시험과 차이가 커서 2.0에서 뺐습니다. 이전 LC 문항 115개와 도구는 `archive/lc/`에 보관되어 있고 배포에는 포함되지 않습니다.

모든 문제는 이 앱을 위해 새로 쓴 오리지널입니다. ETS 기출·시판 교재 문제나 다른 앱의 이름·디자인·문구를 쓰지 않았습니다. TOEIC은 ETS의 등록 상표입니다.

## 바로 열기

| 방법 | 설명 |
|---|---|
| GitHub Pages (권장, 오프라인 설치) | 아래 배포 후 `https://kimheesoo012.github.io/opic/toeic/` → 브라우저 메뉴 "홈 화면에 추가" |
| 정적 파일 zip | `npm run build` → `dist/toeic-trainer-static.zip`. `toeic/` 폴더를 아무 정적 호스팅에 올리면 됩니다. |
| 파일 하나 | `dist/toeic-single.html`. 데이터가 들어 있는 단일 HTML이고 오프라인 설치는 없습니다. |

로컬에서는 `npm run serve` 후 `http://localhost:8765/toeic/`로 엽니다. `toeic/index.html`을 파일로 바로 열면 브라우저가 데이터 JSON 읽기를 막습니다.

## GitHub Pages 배포

1. 이 브랜치(`claude/toeic-trainer`)를 `main`에 병합합니다. 병합하지 않고 2번에서 이 브랜치를 골라도 됩니다.
2. 저장소 **Settings → Pages → Build and deployment → Source: Deploy from a branch** → Branch: `main` / `(root)` → Save.
3. 1~2분 뒤 `https://kimheesoo012.github.io/opic/toeic/`에서 열립니다. 루트 `/opic/`은 기존 OPIc 페이지입니다.
4. 휴대폰에서 한 번 연 뒤 홈 화면에 추가하면 앱처럼 실행되고, 그 뒤로는 오프라인에서도 열립니다.

문제를 추가·수정한 뒤에는 `npm run build`로 `toeic/sw.js`(오프라인 캐시 목록과 버전)를 다시 만들어 함께 커밋해야 휴대폰에 새 버전이 반영됩니다.

## 기능

- **진단**: 간단 진단 20분·약 30문항, 심화 진단 45분·약 60문항(이중·삼중 지문 포함, 유형별 실력과 시간 관리 분석).
- **목표**: 총점 800~990 중 선택. RC 목표 = 총점 − LC 기준 점수(기본 395). 파트별 현재 추정 정답률과 필요 정답률 비교.
- **오늘의 추천**: 10·20·40분 코스. 정답률, 풀이 시간, 오답 원인, 최근 변화, 목표와의 차이로 고르고 추천마다 이유 한 문장.
- **해설**: 정답 이유, 오답 선택지마다 그 문제 문맥으로 쓴 함정 이유, 개념별 핵심 한두 줄. Part 7은 지문 표현과 정답 표현의 바꿔 말하기 짝.
- **오답 원인** 탭 한 번 선택(모르는 어휘·문법·근거 못 찾음·시간 부족·실수·함정), 통계 반영.
- **단계별 복습**: 핵심 개념 → 쉬운 문제 → 어려운 문제 → 제한 시간 → 1·3·7일 뒤 새 문제 → 유지 확인. 같은 문제 재정답과 새 문제 정답을 따로 기록.
- **속도 훈련**: Part 5 연속 풀이(문항당 20초, 시간이 다 되면 자동으로 다음 문항), Part 7 지문별 목표 시간(분당 150단어 + 문항당 25초, 지문마다 80~220초), 시간 초과 문제 모음.
- **실전**: RC 실전 모의고사 100문항 75분(Part 5 30, Part 6 16, Part 7 단일 29 + 이중 2세트 + 삼중 3세트), 하프 모의고사 약 50문항 38분, 파트별 시간 제한.
- **다중 지문 화면**: 지문을 탭으로 전환하고, 본문만 스크롤되며 선택지는 화면 아래에 고정. "지문 크게"로 선택지 영역을 줄일 수 있음.
- **어휘**: 해설에서 단어를 탭하면 뜻과 문제 속 문맥, 단어장 저장, 4지선다 복습.
- **기록**: 파트·유형별 정답률과 평균 시간, 자주 틀리는 유형 TOP 3, 오답 원인 분포, 결과 요약 복사, JSON 내보내기·가져오기(잘못된 파일이면 기존 기록 유지), 풀다가 나가도 이어서 풀기.
- 휴대폰 세로 화면·한 손 조작(선택지 버튼 52px 이상, 글자 16px 이상), 다크 모드, PWA(매니페스트·서비스 워커·아이콘·오프라인).

## 문제은행: 실제 작성·검증한 수

| 파트 | 문항 | 구성 |
|---|---|---|
| Part 5 단문 빈칸 | **205** | 문법 17개 개념 × 9, 어휘 5개 개념 × 10~11. 난이도 기본 54 · 중급 79 · 고급 72 |
| Part 6 장문 빈칸 | **100** | **25세트**, 모든 세트에 문장 삽입 1문항. 이메일·편지·공지·메모·기사·광고·보도자료·웹페이지·설명서 |
| Part 7 독해 | **170** | 단일 지문 **30세트**(95문항), 이중 **8세트**·삼중 **7세트**(75문항). 이메일·문자·온라인 채팅·공지·기사·광고·양식·메모·웹페이지·리뷰·편지·일정표·송장·견적서·채용 공고 |
| 합계 | **475** | 정답 위치 A/B/C/D = 119/118/119/119 |

검증:
- 작성할 때 문항마다 다른 선택지도 문법·의미상 가능한지 검토했고, 다 쓴 뒤 새 문항 전체를 정답 표시만 남긴 목록으로 한 번 더 읽었습니다. 두 번째 검토에서 답이 둘일 수 있는 3곳을 고쳤습니다(p5-192, p5-196, p7-t05 지문).
- 자동 검사(`npm run test:bank`)로 형식, 중복·같은 문장 틀, 오답 해설 순서, 정답 해설이 정답을 짚는지, 개념별 문항 수, 파트·세트 목표 개수를 확인합니다. 이 검사로 해설이 정답을 직접 언급하지 않던 9곳을 고쳤습니다.
- 원어민이나 외부 검수자의 검토는 받지 않았습니다.

### 문제 추가

`toeic/data/*.json`의 `units`에 추가하고 새 파일이면 `data/index.json`의 `files`에 넣습니다. 필드: `id`, `part`, `type`, `concept`(concepts.json의 id), `difficulty`(1 기본·2 중급·3 고급), `choices` 4개, `answer`(0부터), `explanation.why`, `explanation.traps`(선택지 순서, 정답 자리는 `null`), `vocab`, `tags`(["trap"]), `para`[{p, a}]. Part 5는 `question`에 `-------`, Part 6 세트는 `passages` 본문에 `{{1}}`~`{{4}}`와 문항 `blank`, Part 7 세트는 `passages` 1~3개(표는 `table`), 문장 위치 문제는 본문 `— [1] —`와 문항 `sentence`. 2.0에서 추가한 문항은 `tools/authoring/*.py`로 작성한 뒤 `tools/rebalance.py`로 정답 위치를 고르게 했습니다. JSON이 원본입니다.

## RC 추정 점수: 계산 방식과 한계

- **입력**: 최근 90일 RC 풀이의 정답 여부, 난이도, 풀이 시간, 파트별 성취도. 같은 문제 재풀이와 단계별 복습 기록은 제외. 진단·모의고사 가중치 1, 일반 연습 0.6.
- **계산**: 난이도와 찍기 확률을 넣은 문항반응 모델로 능력값 분포를 구하고 실제 시험 파트 비중(Part 7 = 54%)으로 가중 → 파트별 능력값은 전체 쪽으로 수축 → 실제 문항 수와 가정한 난이도 분포로 예상 원점수 → 내 풀이 속도로 75분 안에 못 푸는 문항은 찍는다고 보고 감점 → 근사 환산표로 5~495점.
- **표시**: 「RC 추정 점수 범위」와 「추정」 표시. 능력값 10~90% 구간에 환산표 오차 20점과 안 풀어 본 파트 비중만큼 넓힘. 15문항 미만이거나 파트 비중 절반 이상을 안 풀었으면 「RC 400 도전 단계」 같은 수준만 표시. 최근 RC 점수(기본 360)는 기록이 적을 때만 약하게 반영.
- **한계**: 검증된 환산 모델이 아닙니다. 난이도는 작성자가 매긴 값이고 응시자 데이터로 보정하지 않았습니다. 환산표도 공식 표가 아닙니다. 실제 점수를 정확히 예측하지 않습니다.

## 테스트 (실제로 실행한 것)

`npm test` = 빌드 + 아래 세 가지. 2.0 기준 모두 통과.

1. `test:bank`: 위 문제은행 검사.
2. `test:sim`: 시드 고정 가상 학습자 300명 × 14일(세션 12,404개, 응답 267,917개)로 진단·추천·연습·연속 풀이·지문별 시간 훈련·시간 초과 모음·오답 재풀이·단계별 복습을 반복하며 불변 조건 검사. 진단·심화·하프·실전 모의고사·연속 풀이·지문별 훈련의 구성(문항 수, 실전 모의고사 Part 5 30·Part 6 16·이중 2·삼중 3세트·75분, LC 미포함, 중복 세트 없음)도 검사. 실제 능력과 추정 점수의 순위 상관 ρ≈0.90.
3. `test:e2e`: Playwright Chromium, 휴대폰 화면 390×844와 360×740에서 41~42개 항목 통과. 진단 → 결과 → 목표 → Part 5 즉시 해설·핵심·오답 원인·어휘 저장 → 앱 재실행 후 이어서 풀기 → Part 6 빈칸 강조 → Part 7 이중·삼중 지문 탭 전환·긴 지문 스크롤 시 탭 고정과 선택지 위치·지문 크게 → 지문별 카운트다운 → 연속 풀이 20초 자동 넘김(가상 시계) → 시간 초과 모음 → 단계별 복습 → 실전 모의고사 100문항·75분 → 요약 복사 → 내보내기·잘못된 파일 거부 → 다크 모드 → 가로 스크롤 없음 → 오프라인 재실행. 화면 문구에 안내 말투·이모지·LC 흔적이 없는지도 검사.

실행하지 못한 것: 실제 휴대폰 기기(iOS Safari, Android Chrome) 테스트, Firefox·Safari 엔진 테스트.

## 알려진 제약

- Part 6 고급 문항은 5개뿐이라 고난도 비중을 올리는 데 한계가 있습니다.
- 기록은 기기 브라우저에만 저장됩니다. 다른 기기로는 JSON 내보내기·가져오기로 옮깁니다.
- claude.ai 미리보기 페이지에서는 서비스 워커와 파일 저장이 막혀 오프라인 설치가 안 되고, 내보내기는 클립보드 복사로 대신합니다.
