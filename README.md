# 토익 900 트레이너 (TOEIC L&R 고득점 훈련 PWA)

> 이 저장소 루트의 `index.html`은 기존 OPIc 시뮬레이터이고, 토익 앱은 **`toeic/` 폴더**에 따로 있습니다.

진단 → 약점 분석 → 맞춤 추천 → 즉시 해설·오답 원인 → 단계별 복습 → 실전 연습 흐름의 휴대폰용 학습 앱입니다.
서버·계정·유료 API 없이 정적 파일만으로 동작하고, 기록은 기기 브라우저(IndexedDB)에 저장됩니다.

- 화면·해설은 한국어, 문제는 영어. 세로 화면·한 손 조작(선택지 버튼은 아래쪽, 높이 52px 이상, 글자 16px 이상), 다크 모드.
- 모든 문제는 이 앱을 위해 새로 쓴 오리지널입니다. ETS 기출·시판 교재 문제나 다른 앱의 이름·디자인·문구를 쓰지 않았습니다. TOEIC은 ETS의 등록 상표입니다.

## 바로 열기

| 방법 | 설명 |
|---|---|
| GitHub Pages (권장, PWA·오프라인) | 아래 "GitHub Pages 배포" 후 `https://kimheesoo012.github.io/opic/toeic/` → 브라우저 메뉴 "홈 화면에 추가" |
| 정적 파일 zip | `npm run build` → `dist/toeic-trainer-static.zip`. 압축을 풀어 아무 정적 호스팅(Netlify Drop, Cloudflare Pages 등)에 `toeic/` 폴더를 올리면 됩니다. |
| 파일 하나 | `dist/toeic-single.html` — 데이터가 들어 있는 단일 HTML. 서비스 워커(오프라인 설치)는 없습니다. |

`toeic/index.html`을 파일로 직접 열면(`file://`) 브라우저가 데이터 JSON을 막으므로 로컬에서는 `npm run serve` 후 `http://localhost:8765/toeic/`로 여세요.

## GitHub Pages 배포

1. 이 브랜치(`claude/toeic-trainer`)를 `main`에 병합합니다(또는 2번에서 이 브랜치를 바로 고릅니다).
2. GitHub 저장소 → **Settings → Pages → Build and deployment → Source: Deploy from a branch** → Branch: `main`(또는 `claude/toeic-trainer`) / `(root)` → Save.
3. 1~2분 뒤 `https://kimheesoo012.github.io/opic/toeic/` 에서 열립니다(루트 `/opic/`은 기존 OPIc 페이지).
4. 휴대폰에서 한 번 연 뒤 "홈 화면에 추가"하면 앱처럼 실행되고, 이후에는 오프라인에서도 열립니다.

문제를 추가·수정한 뒤에는 `npm run build`로 `toeic/sw.js`(오프라인 캐시 목록·버전)를 다시 만들어 함께 커밋해야 휴대폰에 새 버전이 반영됩니다.

### 문제 추가하기

`toeic/data/*.json`의 `units` 배열에 추가하고, 새 파일이면 `data/index.json`의 `files`에 넣습니다. 필드:

- 공통: `id`, `part`, `type`, `concept`(concepts.json의 id), `difficulty`(1~5), `choices`(Part 2는 3개, 나머지 4개), `answer`(0부터), `explanation.why`(정답 이유), `explanation.traps`(선택지 순서대로 오답별 함정 설명, 정답 자리는 `null`), `vocab`[{w, pos, m, ex?}], `tags`(["trap"] 고난도), `para`[{p: 지문 표현, a: 정답 표현}]
- Part 1: `image.svg`, `image.alt`(장면 설명), `speakers`
- Part 2: `question`(질문 문장), `speakers` {Q, A}
- Part 3·4 세트: `speakers` {키: {g: m/f, accent: US/GB/AU}}, `script` [{s, t}], `graphic`(표, 선택), `questions`[3개]
- Part 5: `question`에 빈칸 `-------`
- Part 6 세트: `passages`[{kind, title, text}] 본문에 `{{1}}`~`{{4}}`, 각 문항 `blank` 번호
- Part 7 세트: `passages` 1~3개(표는 `table`), 문장 위치 문제는 본문에 `— [1] —`…와 문항 `sentence`

`npm run test:bank`가 형식, 정답 범위, 오답 해설 정렬, 중복·같은 문장 틀(유사도) 등을 검사하고, 앱도 시작할 때 같은 검사로 문제가 있는 항목은 빼고 실행합니다.

검증 방법: 작성 후 문항마다 다른 선택지도 문법·의미상 가능한지 한 번 더 검토했고, 그 과정에서 답이 둘일 수 있는 문항 6개를 고치거나 바꿨습니다. 자동 검사(`test:bank`)로 형식·중복·해설 순서(정렬이 어긋난 해설 2건 수정)를 확인했고, 정답이 A에 몰려 있던 것(221/72/43/10)을 고르게 재배치했습니다(현재 90/90/90/76, 숫자·위치 선택지 12개는 순서 유지). 원어민·외부 검수자의 검토는 받지 않았습니다.

## 추정 점수 계산 방식과 한계

- **입력**: 최근 90일 기록의 정답 여부, 문항 난이도(1~5), 풀이 시간, 파트별 성취도. 같은 문제 재풀이·단계별 복습 기록은 제외, 진단·모의고사 가중치 1, 일반 연습 0.6.
- **계산**: 섹션(LC/RC)별로 난이도와 찍기 확률을 넣은 문항반응 모델로 능력값 분포를 구하고(실제 시험 파트 비중으로 가중), 파트별 능력값은 섹션 값 쪽으로 수축 → 실제 시험 파트별 문항 수·가정한 난이도 분포로 예상 원점수 → RC는 내 풀이 속도로 75분 안에 못 푸는 문항을 찍는다고 보고 감점 → 경험적 근사표로 5~495점 환산.
- **표시**: 능력값 10~90% 구간 + 환산표 오차 ±20점 + 안 풀어 본 파트 비중만큼 넓힌 **범위**와 「추정」 표시. LC 8문항·RC 10문항 미만 또는 섹션 파트의 절반 이상을 안 풀었으면 점수 대신 학습 수준(예: 「800 도전 단계」)만 보여 줍니다. 목표 화면에 입력한 최근 실제 점수(기본 LC 395·RC 360)는 기록이 적을 때만 약하게 반영됩니다.
- **한계**: 검증된 환산 모델이 아닙니다. 난이도는 작성자가 매긴 값이고 응시자 데이터로 보정하지 않았으며, 원점수→환산 표도 공식 표가 아닙니다. TTS 음성은 실제 녹음과 달라 LC 오차가 더 큽니다. 실제 점수를 정확히 예측하지 않으며 학습 방향을 잡는 참고치입니다.

## 테스트 (실제로 실행한 것)

`npm test` = 빌드 + 아래 세 가지.

1. `test:bank` — 문제은행 형식·중복·해설 정렬·개념별 문항 수·파트별 개수 검사. **통과**(경고: `p1.scene`, `p4.graphic` 개념은 문항이 2개뿐).
2. `test:sim` — 시드 고정 가상 학습자 300명 × 14일(세션 13,294개, 응답 222,960개)로 진단·추천·연습·속도·시간 제한·오답 재풀이·단계별 복습을 반복하며 불변 조건 검사(예외 없음, 점수 범위 역전 없음, 추천 이유 문장, 복습 단계·날짜 정상, 세션 무한 반복 없음). **통과**, 실제 능력과 추정 점수의 순위 상관 ρ=0.938.
3. `test:e2e` — Playwright Chromium, 휴대폰 화면(390×844, 360×740)에서 35~36개 항목(무작위 응답에 따라 조건부 항목 1개) **모두 통과**: 진단 → 결과 → 목표 → 추천 학습(즉시 해설·오답 원인) → 어휘 탭·저장 → 중간 종료 후 이어서 풀기 → 단계별 복습 → 하프 모의고사 중간 종료 → 심화 진단(유형별·시간 관리) → 결과 요약 복사 → JSON 내보내기·잘못된 파일 거부(기존 기록 유지)·가져오기 → 훈련 화면 → 다크 모드 → **오프라인 재실행(서비스 워커)**. 가짜 음성(미국·영국·호주·한국어) 환경과 음성 없는 환경을 각각 확인.

실행하지 못한 것: 실제 휴대폰(iOS Safari, Android Chrome) 기기 테스트, 실제 기기 음성으로 듣는 품질 확인, Firefox·Safari 엔진 테스트.

## 구현하지 않은 것 / 알려진 제약

- 120분 풀 모의고사: 청사진은 있지만 Part 3이 12세트(13세트 필요)라 화면에 넣지 않았습니다.
- 고난도(난이도 5) 문항이 Part 5에만 8개라 950·990 목표에서 어려운 문제 비중을 크게 올리기에는 문제가 부족합니다.
- Part 1은 사진 대신 단순 SVG 그림이고 8문항뿐입니다.
- 기록은 기기 브라우저에만 저장됩니다(동기화 없음). 다른 기기로는 JSON 내보내기·가져오기로 옮깁니다.
- 음성 합성의 오프라인 동작은 기기·음성마다 다르며 보장하지 않습니다. 음성이 없으면 스크립트를 보며 진행합니다.
